# AFSR Math

초등학생이 매일 사칙연산을 연습하고, 오답을 복습하며, 자신의 학습 기록을 확인하는 한국어 웹 애플리케이션입니다.

## 로컬 실행

- Node.js 24.15 이상 또는 22.22.3 이상 권장 (이 저장소는 Node 24.19.0을 고정)
- Node 버전 선택: `nvm use` (Node 24.19.0)
- 의존성 설치: `npm install`
- 개발 서버 (중단 시 자동 재시작): `npm run dev`
- 개발 서버 단일 실행: `npm run dev:once`
- 단위 테스트: `npm test`
- TypeScript 검사: `npm run typecheck`
- Vercel 프로덕션 빌드: `npm run build`
- Node 서버용 로컬 빌드: `npm run build:local`

처음 방문하면 학습 수준을 선택하고, 오늘의 학습을 시작하거나 `/practice`에서 자유 학습 조건을 고릅니다. 기록은 기본적으로 브라우저 IndexedDB에 저장합니다. 브라우저의 사이트 저장 데이터를 삭제하기 전에 설정 화면에서 JSON 백업을 내려받아 주세요.

## 학습·복습 규칙

- 첫 오답은 지정 세션 안에서 두 번 더 풀 수 있고, 세 번째 오답 뒤 답을 보여 줍니다. 정답률은 첫 답안 기준이며 재시도와 복습은 별도 기록입니다.
- 오답은 다음에 실제로 시작한 학습 세션에서 별도 간격 복습 묶음으로 나옵니다. 복습에서 틀리면 다음 세션, 맞히면 3회차 학습 세션 뒤에 확인하며 그 확인도 맞히면 복습 큐에서 종료됩니다. 휴식일과 미학습일은 회차에 반영되지 않습니다. 기본 상한은 세션당 5문제이며 `/settings`에서 3·5·8·10문제로 조정할 수 있습니다.
- `/plan`은 최근 완료된 최대 5개 세션의 최초 답안에서 유형별 표본이 3개 이상인 경우 최대 2개 집중 유형을 중립적으로 제안합니다. 추천은 계획 초안에 반영되며 저장 전 기존 기록과 진행 중인 과제는 바뀌지 않습니다.
- `/practice`에서 연산 판단 혼합을 선택하면 이전 학습 기록이 있는 선택 연산만 사용하고 문제 기호를 숨겨 연산을 직접 선택하게 합니다. 선택한 자릿수·난이도·받아올림·나머지 조건은 그대로 지킵니다.
- 풀이 시간은 참고 정보로만 보여 주며 시간 제한을 두지 않습니다.

## 구현

- `domain/`: 순수 TypeScript 문제 생성, 세로셈 기반 carry/borrow 난이도, 계획 배분, 채점, 복습, 성장 비교
- `shared/`: Zod 데이터 모델과 검증
- `repositories/`: IndexedDB와 Nuxt 서버 저장소, 충돌 감지, JSON 백업/복원
- `app/`: 반응형 한국어 홈, 자유 학습, 풀이, 결과, 복습, 기록 달력, 계획, 데이터 설정
- `server/api/cloud/`: 가족 로그인 세션으로 보호된 클라우드 API. 클라우드 설정이 불완전하면 HTTP 503을 반환
- `supabase/migrations/`: 단일 학습 상태 스냅샷의 revision CAS와 비공개 RLS 정책. 세 번째 마이그레이션에서 앱이 사용하지 않던 파생 테이블을 보관 스키마로 이동
- `tests/database.test.ts`: 실제 앱 상태를 PostgreSQL 호환 엔진에 저장·복원하는 스키마 계약 테스트
- `docs/WORKFLOW.md`: 분석 → 설계 → 구현 → 테스트 → 완성 과정

문제 난이도는 자리별 받아올림/받아내림과 학교 세로셈의 곱셈 올림을 기준으로 결정합니다. 나눗셈은 긴 나눗셈 몫의 자릿수 및 나누는 수의 구조를 사용합니다. 생성기는 출제 가능한 조합을 열거하거나 제한된 시도로 모으고, 중복·고갈 때 안내 오류를 반환합니다. 나머지가 있는 나눗셈은 몫과 나머지를 별도로 채점합니다.

## Supabase 연결 및 보안

이 앱은 가족이 하나의 학습 기록을 공유하는 개인용 저장소입니다. Supabase 프로젝트에는 `supabase/migrations/202610130001_initial.sql`, `supabase/migrations/202610150001_spaced_review_schema.sql`, `supabase/migrations/202610160001_single_state_contract.sql`을 순서대로 적용합니다. 데이터 기준은 `public.app_state` 한 행이며 자세한 계약은 [저장 계약](docs/STORAGE_CONTRACT.md)에 있습니다.

Vercel 프로젝트의 **Production 환경변수**에 아래 값을 등록하고 새 배포를 만듭니다. Preview에는 운영 DB 키를 넣지 않습니다. 실제 값은 Git에 올리지 않습니다.

```dotenv
NUXT_CLOUD_ENABLED=true
NUXT_CLOUD_ACCESS_TOKEN=<16자 이상의 고유한 가족용 암호 문장>
NUXT_SUPABASE_URL=https://<project-ref>.supabase.co
NUXT_SUPABASE_SERVICE_KEY=<Supabase 서버 전용 secret 키 또는 기존 service_role 키>
```

`NUXT_CLOUD_ENABLED=true`이면 앱은 처음부터 클라우드 저장소를 선택합니다. 가족은 URL에 접속한 뒤 공용 암호를 한 번 입력합니다. 16자 이상의 기억하기 쉬운 고유한 문장을 사용할 수 있으며, 브라우저의 암호 저장 기능을 이용하면 다시 입력할 필요가 줄어듭니다. 서버는 30일 동안 유효한 서명된 HttpOnly/SameSite 쿠키를 발급하고, 모든 클라우드 요청에서 확인합니다. 암호와 Supabase 서버 키는 클라이언트 코드에 포함하지 않습니다. 클라우드 설정이 불완전하거나 서버 연결이 실패하면 로컬에 조용히 저장하지 않고 오류를 표시합니다. `NUXT_CLOUD_ENABLED=false`이면 IndexedDB 로컬 모드입니다. 자동 로컬 기록 이전은 제공하지 않습니다.

이 방식은 **가족이 같은 기록을 사용하는 단일 저장 공간**이며, 사용자별 계정이나 기록 분리는 제공하지 않습니다. 가족 공용 암호가 유출되면 Vercel 환경변수에서 교체하고 재배포해야 합니다. 공개 URL을 공유할 때는 다른 사이트에서 사용하지 않는 암호 문장을 선택하고 `123456` 같은 짧고 흔한 암호는 사용하지 마세요.

## 알려진 제한

- 회원가입, AI 생성/채점, 자동 로컬/클라우드 동기화는 구현하지 않았습니다.
- 자동 브라우저 E2E는 `npm run test:e2e`로 실행할 수 있으며 앱과 분리된 로컬 포트를 사용합니다.
- Supabase 연결 및 Vercel 배포는 사용자의 프로젝트와 보호 환경 설정이 필요합니다. 이 저장소에서는 외부 계정에 연결하거나 배포를 완료했다고 표시하지 않습니다.
