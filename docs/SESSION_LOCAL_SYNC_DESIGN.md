# 풀이 중 로컬 저장, 종료 시 클라우드 반영 설계

상태: 구현됨. 이 문서는 구현 기준과 검증 범위를 기록한다.

## 목표와 현재 병목

클라우드 모드의 `useLearning().mutate()`는 답안·재시도·복습 위치 변경마다 `/api/cloud/state`를 GET하고 전체 `AppState`를 PUT한다. 서버도 Supabase의 단일 `app_state` 행을 읽고 전체 JSON 스냅샷을 revision CAS로 저장한다. 문제마다 네트워크 왕복과 전체 상태 전송을 기다리므로 풀이 반응이 느리다.

목표는 답안 제출 시 채점과 진행 표시를 로컬 IndexedDB 저장 완료 직후 수행하고, **풀이 중에는 Supabase 쓰기를 하지 않는 것**이다. 세션 완료 또는 사용자의 `저장하고 나가기` 시 한 번 동기화한다. 결과 화면의 `서버 저장 완료`는 Supabase가 실제로 성공 응답을 준 경우에만 표시한다.

## 권장 흐름

1. **시작:** 서버에서 최신 상태와 revision을 읽고 세션을 생성·예약한다. 일일 과제의 중복 생성과 복습 배정을 막기 위해 이 시점에 서버 쓰기 한 번은 허용한다. 시작 시 왕복은 남지만 문제별 왕복은 없어진다. 생성된 세션의 문제·설정·복습 배정은 스냅샷으로 고정한다.
2. **풀이:** `submit`, `queueWrongAnswer`, `submitSpacedReview` 등 기존 도메인 함수를 브라우저에서 적용한다. 매 답안의 결과와 현재 위치를 IndexedDB의 세션 초안에 트랜잭션으로 기록한다. 로컬 저장이 실패하면 다음 문제로 이동하지 않는다. Supabase 요청은 하지 않는다.
3. **종료:** 일반 문제를 모두 해결해 `status=completed`가 되는 순간, 또는 사용자가 `저장하고 나가기`를 누르면 초안을 `동기화 대기`로 표시하고 서버에 전송한다. 유사 복습·간격 복습을 나중에 진행한 경우에도 해당 묶음을 마칠 때 전송한다. 결과 화면 이동은 로컬 저장 직후 허용하되 서버 저장 상태를 분명히 표시한다.
4. **재접속:** 클라우드 상태를 불러오기 전에 IndexedDB의 미동기화 초안을 확인한다. 같은 기기에서는 중단 위치를 복원한다. 이미 종료된 초안은 재전송한다. 로그인 만료나 네트워크 오류가 있으면 초안을 보존하고 재로그인·재시도를 안내한다.

브라우저 탭 닫기나 기기 전원 종료 시 전송 성공을 보장할 수 없다. `beforeunload`나 `sendBeacon`은 보조 수단으로만 사용하고, IndexedDB 초안을 복구의 기준으로 삼는다. 다른 기기는 동기화가 끝나기 전의 답안을 볼 수 없다.

## 저장 단위와 충돌 처리

IndexedDB에는 서버에서 받은 기준 revision, 세션 ID, 고정된 문제·설정 스냅샷, 답안·재시도·복습 시도, 현재 위치, 로컬 변경 순번, `local-only | syncing | synced | failed` 상태를 저장한다. **서버 원본 상태와 로컬 초안을 별도로 보관**하며, 클라우드 모드에서 로컬 전체 상태를 그대로 서버에 덮어쓰지 않는다.

종료 API는 `sessionId`, 기준 revision, 세션의 변경 내역과 고유한 `commitId`를 받는다. 서버는 최신 `app_state`에 변경 내역을 재적용하고 `stateSchema`로 검증한 뒤 기존 `save_learning_state`의 revision CAS로 저장한다. 이미 적용한 `commitId`를 서버 상태의 동기화 메타데이터에 보관해 동일 요청의 재시도가 답안을 중복 추가하지 않도록 한다. 다른 세션이나 계획만 바뀌었다면 최신 상태에 재적용한다. **같은 세션 또는 같은 복습 항목이 다른 기기에서 수정되었다면 자동 덮어쓰지 않고 충돌을 표시**한다. 복습 큐와 `sessionCounter`는 서버의 최신 상태를 기준으로 계산해 간격을 앞당기거나 중복 배정하지 않는다.

단일 스냅샷 SQL 구조는 유지한다. `session.syncCommitIds`를 선택적 기본값으로 추가해 기존 v2 상태도 읽을 수 있게 했다. 종료 API는 동일 `commitId`의 재시도를 중복 적용하지 않는다. 같은 일일 과제를 여러 기기에서 동시에 수정하거나 같은 복습 항목을 수정하면 409 충돌로 초안을 보존한다. 이 경우 자동 병합은 하지 않는다.

## 사용자에게 보이는 상태

- 풀이 중: `이 기기에 저장됨`.
- 종료 후 전송 중: `서버에 저장 중`.
- 성공 응답 후: `서버 저장 완료`.
- 오프라인·인증 만료·충돌: `이 기기에 보관됨 · 서버 저장 필요`와 재시도 버튼.

`저장하고 나가기`는 전송 실패 시에도 초안이 안전하게 남았다는 사실을 알려야 한다. 기록 삭제·JSON 복원·계획 변경은 미동기화 초안이 있을 때 조용히 실행하면 안 된다. 먼저 동기화하거나 초안을 명시적으로 폐기하도록 한다.

## 검증 기준

1. 한 문제를 풀 때 Supabase 호출은 0회이고, 채점·다음 문제 전환은 로컬 저장 완료 후 진행한다.
2. 마지막 문제와 `저장하고 나가기`에서 종료 동기화가 각각 한 번 실행된다. 유사 복습과 간격 복습도 별도로 동기화된다.
3. 풀이 도중 새로고침·탭 종료·오프라인 전환 뒤 같은 기기에서 답안과 현재 위치가 복원된다.
4. 저장 실패·401·409 후 초안이 남고, 재시도 시 최초 답안과 재시도가 중복되지 않는다.
5. 다른 기기의 계획 변경이나 다른 세션 완료는 보존한다. 같은 세션·복습 항목의 충돌은 자동 덮어쓰지 않는다.
6. 복습 큐의 중복 출제, `sessionCounter` 간격 오류, 일일 과제 중복 생성이 발생하지 않는다.
7. 기록이 많은 상태에서 문제별 응답 시간과 전송량을 변경 전과 비교한다. 측정값 없이 성능 향상을 수치로 주장하지 않는다.

## 구현 순서

IndexedDB 초안과 복구, 답안의 로컬 저장, 기존 시작 시 서버 저장, 종료 전송 API, 서버 충돌·중복 처리, 저장 상태 UI를 구현했다. 단위·브라우저 테스트를 추가했으며 실제 Supabase 프로젝트를 통한 통합 검증은 별도로 필요하다. 기존 클라우드 기록은 서버 기준으로 읽고, 새 로컬 초안은 세션 단위로만 추가한다. 과거 로컬 기록의 일괄 이전은 포함하지 않는다.
